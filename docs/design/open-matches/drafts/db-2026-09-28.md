## 2. Database core (lane DB)

This lane writes 0249, 0253, the match half of 0254, 0256, 0257, the non-money half of 0258, 0259
and 0260. It also fixes the contract for 0252, which §1.1 gives to Guest: every match read depends

### 2.1 What the code forces

- **One live row per court.** `reservations_no_overlap` covers `status in
  ('pending','confirmed','arrived')` (0008:42-45), and a booking needs `guest_id` or `guest_name`
  (0008:38). The match booking is therefore `kind='booking'`, `guest_id` NULL, `guest_name 'Open
  match'`.
- **A NULL `guest_id` keeps the booking away from every guest path.** Guest RLS (0008:685-686),
  `cancel_reservation` (0210:567-569, FORBIDDEN), `my_reservations` (0242:1733) and the booking push
  (0090:143) all key on `guest_id`. Players reach the match only through §2.9.
- **Firm rows appear in three ways.**
  - Insert as `confirmed`: `staff_create_reservation` (0217:1367, `lock_court` at :1438); series
    through it (0231:244, :287); event blocks (0174:748-752); the deposit re-create (0242:560-561).
  - Hold → booking in place, with no court lock: `confirm_booking` (FOR UPDATE at 0242:1326, UPDATE
    at :1402) and `deposit_settle_success` (0242:541).
  - Move or extend: `move_reservation` (0150:37), `extend_reservation` (0071:444).
  So the trigger watches INSERT and UPDATE OF `kind, status, court_id, start_at, end_at`.
- **Advisory locks.** `app.lock_court` is `pg_advisory_xact_lock(hashtextextended(
  'app.reservations:court:'||id, 0))` (0042:50-58), and nothing else in the schema uses one.
- **The lock gate** (`packages/db/scripts/check-lock-order.mjs`): `ORDER` ends `court_advisory →
  reservations` (:37-49); only `lock_court` is emitted as an advisory lock (:137); only
  anon/authenticated functions are walked (:166-172); rule 3 wants `lock_court` before any
  `reservations` FOR UPDATE, except the status-only writers (:215-222); every trigger of a written
  table is expanded whatever its WHEN; compaction drops only consecutive repeats (:228).
- **The branch guard.** `row_venue` falls back to `select venue_id from public.<parent>`
  (0230:78-79), so a chain-wide parent with no `venue_id` can never be named in a link pair. A staff
  writer passes only when `app.venue_id` is asserted, when the row is their own guest booking, or
  when `is_staff_at` holds (0230:150-165). A staff member confirming their own hold reaches the
  match trigger, so that trigger asserts `app.venue_id` itself.
- **`customer_flags`** is global with PK `(customer_id, type)` (0065:86-93), widened at
  0241:187-197. `set_customer_flags` deletes every flag and re-inserts the list it is sent
  (0242:1789), and court_desk may call it (0242:1756). A ban kept there disappears on the next
  flag edit unless it is carried over.
- **Profiles.** `full_name` is NOT NULL and ≤ 80 (0116:97-101). It can be `''`: the sanitiser turns
  an all-control name into `''` (0080:130-140). `handle_new_user` builds it from metadata
  (0069:204). The app already sends `given_name`/`family_name` (`apps/mobile/src/features/auth/api.ts:51-55`).
  The guest update grant is at 0004:161; the select grant was narrowed at 0077:301-303.
- **`delete_my_account`** (0077:120-277) keeps a tombstone (:187-192), scrubs the guest's
  reservations (:209-217), deletes their flags (:226) and outbox rows, and refuses staff
  (:153-155).
- **Terms.** `terms_version` matches `^[0-9]{4}-[0-9]{2}-[0-9]{2}(\.[0-9]{1,3})?$` (0153:47-56). No
  server-side terms check exists yet.
- **`mark_reservation`** (0089:42) allows `no_show` only from `confirmed` and only after start
  (:62-76), and the operator replays it offline as `reservation.update`.
- **Business day.** `app.venue_business_date` (0211:29); `day_status` is `open | closing | closed`
  (0002:23).
- **Cron.** 30 s with a per-minute fallback (0242:1811-1822).
- **Gates that read error text.** The matrix counts `FORBIDDEN|AUTH_REQUIRED|ACCOUNT_REQUIRED|
  SESSION_EXPIRED` as "guarded" (`tests/rls-matrix.test.ts:47-51`). A guest RPC must therefore answer
  a nil id with its own not-found before any business FORBIDDEN. `check-rpc-authz` accepts
  ACCOUNT_REQUIRED as a refusal (`scripts/check-rpc-authz.mjs:98`).
- **Codes already mapped.** Mobile maps `COURT_NOT_FOUND`, `AUTH_REQUIRED`, `FORBIDDEN`
  (`apps/mobile/src/features/booking/errors.ts:32,47,48`). The operator maps `VENUE_MISMATCH`,
  `INVALID_ARGUMENT`, `COURT_NOT_FOUND`, `INVALID_DURATION`, `CLOSED_DATE`, `OUTSIDE_HOURS`,
  `NO_RATE`, `IDEMPOTENCY_CONFLICT` and `GUEST_REQUIRED` (`apps/operator/src/lib/errors.ts`).
  `CUSTOMER_NOT_FOUND` is on `fixtures/error-codes-unmapped.json:23`.
- **`notify_staff`** has a closed title-key list inside its body (0193:46-55).

### 2.3 Tables (0254)

Rules for every table below:
- RLS is on. `revoke all … from anon, authenticated; grant all … to service_role` (the 0241:93-97
  form). There are no policies and no client grants: every read and write goes through a
  definer body. The select rows in the matrix are `denied` for all eight principals.
- Branch tables carry `zz_branch_guard` in 0254 with the pairs named. A link to a chain-wide table
  (`match_tickets`, `match_blocks`, `profiles`, `staff`) is never a pair (§2.1).
- `venue_id` has no default: every writer names it from the match, as `hold_slot` does
  (0225:190-196).
- Chain-wide tables (`match_tickets`, `match_ticket_events`, `match_blocks`) have no `venue_id`
  and no guard, like `customer_flags`.

#### 2.3.1 `matches` (branch)

```sql
create table matches (
  id                  uuid primary key default gen_random_uuid(),
  venue_id            uuid not null references venues(id),
  status              text not null default 'filling' check (status in
                        ('filling','awaiting_court','booked','played','no_show','cancelled','bumped','expired')),
  start_at            timestamptz not null,
  end_at              timestamptz not null,
  period              tstzrange generated always as (tstzrange(start_at, end_at, '[)')) stored,
  duration_min        int not null check (duration_min between 30 and 480),
  visibility          text not null check (visibility in ('public','link')),
  join_policy         text not null check (join_policy in ('open','approve')),
  category            text not null check (category in ('open','women','men')),
  price_iqd           iqd not null,
  shares_iqd          bigint[] not null,
  rate_rule_id        uuid references rate_rules(id),
  price_court_id      uuid not null references courts(id),
  fill_deadline_at    timestamptz not null,
  share_token         text not null unique check (share_token ~ '^[A-Za-z0-9_-]{22}$'),
  organiser_id        uuid references profiles(id),
  organised_by        text not null check (organised_by in ('guest','desk')),
  created_by_staff_id uuid references staff(id),
  reservation_id      uuid references reservations(id),
  sandbox             boolean not null default false,
  deadline_warned_at  timestamptz,
  ended_at            timestamptz,
  ended_reason        text check (ended_reason is null or ended_reason in
                        ('organiser_cancelled','staff_cancelled','reservation_cancelled','called_off_short',
                         'bumped','deadline','empty','venue_closed','no_court','all_no_show')),
  idempotency_key     text unique check (idempotency_key is null or char_length(idempotency_key) between 1 and 200),
  created_at          timestamptz not null default now(),
  updated_at          timestamptz not null default now()
);
```

| Constraint | Rule |
| --- | --- |
| `matches_time` | `end_at > start_at and end_at - start_at = duration_min * interval '1 minute'` |
| `matches_shares` | `cardinality(shares_iqd) = 4`, every element ≥ 0, `shares_iqd[1]+shares_iqd[2]+shares_iqd[3]+shares_iqd[4] = price_iqd`, non-increasing, `shares_iqd[1] - shares_iqd[4] <= 1` (plain arithmetic, no function, so no grant trap) |
| `matches_deadline` | `status <> 'filling' or fill_deadline_at < start_at`. This is scoped to filling so a desk move of a booked match can never violate it (critic M4). |
| `matches_organiser_policy` | `organiser_id is not null or join_policy = 'open'` |
| `matches_organised_by` | `(organised_by = 'desk') = (created_by_staff_id is not null)` |
| `matches_reservation` | `status not in ('filling','awaiting_court') or reservation_id is null`; `status not in ('booked','played','no_show') or reservation_id is not null or sandbox` |
| `matches_sandbox_no_court` | `not sandbox or reservation_id is null` (DF-19) |
| `matches_ended` | `(status in ('played','no_show','cancelled','bumped','expired')) = (ended_at is not null)`; `(status in ('no_show','cancelled','bumped','expired')) = (ended_reason is not null)`; `status <> 'bumped' or ended_reason in ('bumped','no_court')`; `status <> 'expired' or ended_reason in ('deadline','no_court')`; `status <> 'no_show' or ended_reason = 'all_no_show'`; `status <> 'cancelled' or ended_reason in ('organiser_cancelled','staff_cancelled','reservation_cancelled','called_off_short','empty','venue_closed')` |

Indexes:
- `matches_reservation_key` unique `(reservation_id) where reservation_id is not null`;
- `matches_live` `(venue_id, start_at) where status in ('filling','awaiting_court','booked')`;
- `matches_deadline_due` `(fill_deadline_at) where status = 'filling'`;
- `matches_organiser` `(organiser_id) where organiser_id is not null`.

Guard: `trg_branch_guard('scoped', 'reservations','reservation_id', 'rate_rules','rate_rule_id',
'courts','price_court_id')`.

Comment: *"0254. An open match at one branch: four seats, a price stamped at start (DF-3), no court
while filling (OM-13). reservation_id is the booking made at 4/4 (guest_id NULL, guest_name 'Open
match'). Written only by the app.match_* and desk match functions."*

Comment: *"0254. One seat of an open match. account = the player; friend = a +1 backed by the

| `profiles_gender_stamp` | `(gender is null) = (gender_set_at is null) and (gender is null) = (gender_set_by is null) and (gender_set_by is null or gender_set_by in ('guest','staff'))` |

`concat_ws(' ', given, family)` is at most 79 characters, so the 0116 `≤ 80` rule always holds.

**Grants.** `grant select (given_name, family_name, gender, gender_set_at, gender_set_by) on profiles
to authenticated` (row access is still `profiles_select`, own row or staff); `grant update
(given_name, family_name) on profiles to authenticated`. Gender has no update grant: only
`set_my_gender` and `staff_set_customer_gender` write it. No `assistant_readable_columns` rows for
the five columns.

**`app.split_person_name(p text) returns text[]`** (immutable, internal; returns `{given, family}`):
1. Tokens = `regexp_split_to_array(btrim(p), '\s+')`. An empty or NULL input gives `{NULL,NULL}`.
2. `n = 1`. If token 1, folded by `lower()` with `أ/إ/آ → ا`, is in `{عبد, ابو, abd, abdul, abdel,
   abdal, abu, abou}` and a second token exists, `n = 2`. If then token 2 is `al`, `el` or `ال` and a
   third token exists, `n = 3` ("Abd al Rahman").
3. `given = left(tokens[1..n] joined by ' ', 39)`, rtrimmed. `family = nullif(left(tokens[n+1..]
   joined, 39), '')`, rtrimmed. The clamp means an 80-character legacy name never breaks the CHECKs.

**`app.name_initial(p_family text) returns text`** (immutable, internal):
1. `s = btrim(p_family)`.
2. Strip one leading article: `آل` or `ال` followed by a space, hyphen or tatweel (`آل ياسين` →
   `ياسين`); an attached `ال` when at least two letters remain (`الربيعي` → `ربيعي`); Latin
   `al-`/`el-`/`al `/`el ` in any case (`Al-Rubaie` → `Rubaie`).
3. Return the first character matching `[[:alpha:]]`, `upper()`d. NULL when there is none.
4. `آلاء` is kept whole (no separator after `آل`). A family name beginning with a non-article `ال`
   (`الياس`) loses it: a known limit, listed in open questions.

**`app.trg_profile_names()`** (definer), trigger `profiles_sync_names` BEFORE INSERT OR UPDATE OF
`full_name, given_name, family_name, deleted_at`. It sorts after `profiles_sanitise`, so it sees
clean text. Rules, in order:
1. `deleted_at is not null`: `given_name`, `family_name`, `gender`, `gender_set_at`,
   `gender_set_by` := NULL; return.
2. `current_setting('app.skip_name_sync', true) = 'on'`: return (the backfill only).
3. `''` parts become NULL.
4. INSERT with `given_name` NULL: parts := `split_person_name(full_name)`.
5. INSERT with `given_name` set, or UPDATE where a part is distinct from OLD: `full_name :=
   concat_ws(' ', given_name, family_name)` (parts win, also when `full_name` changed in the same
   UPDATE).
6. UPDATE where only `full_name` changed (older builds, desk-created customers): parts :=
   `split_person_name(full_name)`.

**`trg_sanitise_profile`** is re-issued from 0080:130 with `given_name := app.safe_line(given_name)`
and `family_name := app.safe_line(family_name)`. The `profiles_sanitise` trigger becomes BEFORE
INSERT OR UPDATE OF `full_name, phone, given_name, family_name`.

**`handle_new_user`** is re-issued from 0069:204, unchanged except that the insert also writes
`given_name = nullif(left(btrim(v_meta->>'given_name'), 39), '')` and `family_name =
nullif(left(btrim(v_meta->>'family_name'), 39), '')`. Rule 5 then rewrites `full_name` from the
parts when both came in. With no parts (phone OTP, Apple relay, desk-created), rule 4 splits
whatever `v_name` resolved to.

**Backfill** (a WHERE-guarded UPDATE inside `set_config('app.skip_name_sync','on', true)`), for

- when `concat_ws(' ', btrim(meta.given_name), btrim(meta.family_name)) = full_name` in
  `auth.users.raw_user_meta_data`, take the clamped metadata parts;
- otherwise take `split_person_name(full_name)`.

Reset the setting afterwards.

`AUTH_REQUIRED`, `ACCOUNT_REQUIRED` (no profile or `deleted_at` set), `INVALID_ARGUMENT` (not

### 2.7 Locks

The order is §1.4: `court_advisory → reservations → match_venue_advisory → match_tickets`. There
are two levels:

| Level | Takes | Used by |
| --- | --- | --- |
| **L1** | `lock_match_venue(venue)` only | `match_request`, `match_withdraw`, `match_decide` (decline), `match_leave`, `match_remove_player`, `match_cancel`, `desk_remove_seat`, `desk_cancel_match`, the reservation trigger (on top of the writer's own locks) |
| **L2** | `match_lock(id)`: every active court in id order → `expire_stale_holds` per court → the booking row FOR UPDATE → `lock_match_venue` | `match_join`, `match_decide` (approve), `desk_add_seat`, `mark_match_seats`, `desk_call_off_short`; starts use `match_lock_courts` + `lock_match_venue` |

Rules:
- Only L2 bodies write `reservations`: `match_try_book`'s insert, and the status updates in
  `mark_match_seats` and `desk_call_off_short`. Hold expiry always runs before the mutex.
- The booking row is locked before the mutex. A status-only writer (`cancel_reservation` 0210:558,
  `mark_reservation` 0089:57) holding that row and waiting on the mutex then meets a transaction that
  waits on the row, never one holding the mutex (critic M2).
- `matches`, `match_seats` and `match_requests` are never FOR UPDATE. Two columns are written
  outside the mutex, on purpose, because no state reads them:
  - the identity scrub in `delete_my_account` (`guest_name`, `guest_phone`, `gender`);
  - Money's `written_off_*` columns.
- Tickets are always locked FOR UPDATE in `id` order, by `ticket_pick`, `ticket_lock`,
  `ticket_release`, `ticket_forfeit`, `ticket_restore` and Money's cash-out.
- A blocking body only ever holds one venue's mutex. The reservation trigger re-takes the same
  venue's mutex inside an L2 body: that is re-granted without waiting.
- The sweep holds one venue's locks by blocking. Every later venue in the same run is taken with
  `pg_try_advisory_xact_lock` and is skipped when that fails (§2.12.2). The sweep can then never
  wait on a court while it holds tickets, which is what made a cross-venue cycle possible.

**Gate changes** (`scripts/check-lock-order.mjs`):
- Append `'match_venue_advisory', 'match_tickets'` after `'reservations'` in `ORDER` (:37-49).
- Emit `{lock:'match_venue_advisory'}` for `/\bapp\.lock_match_venue\s*\(/gi` beside the
  `lock_court` rule (:137), and skip that name in the call list.
- Emit `match_venue_advisory` once per sequence: a later one in the same expanded sequence is
  dropped as re-entrant. Without this, the trigger expanded under `match_join` reads as `match_tickets
  → match_venue_advisory`.
- Walk the service-role functions named in §1.4 (`match_sweep`, `deposit_apply`,
  `ticket_settle_success`) as an explicit list appended to `callable` (:166-172), not every
  service-role function.
- `pg_try_advisory_xact_lock` is not emitted, which is correct: it never waits.
- `packages/db/CLAUDE.md` gets the new order line.

#### 2.8.3 Courts and booking

**`app.match_shares(p_price bigint) returns bigint[]`** (immutable): `floor(p/4)` each, plus 1 on

**`app.match_court_free_firm(p_venue uuid, p_period tstzrange, p_duration_min int, p_need int

`p_duration_min` have no **firm** row overlapping. Firm means `kind in ('booking','maintenance') and
status in ('confirmed','arrived')`. Callers evaluate it in a statement **after** taking the mutex,
so under READ COMMITTED it sees every booking committed by the previous holder (the two-tills race).

**`app.match_pick_court(m matches) returns uuid`**: the first active court of `m.venue_id` offering

1. `id = m.price_court_id` first (the tapped court);
2. then courts whose `price_slot(...)` equals `m.price_iqd`;
3. then that price ascending (nulls last), `sort_order`, `id`.

It returns NULL when none. The caller holds every court lock and has expired stale holds.

**`app.match_try_book(p_match_id uuid) returns text`** (the caller holds L2; returns the new
status):
1. Re-read the match. Return its status unchanged unless it is `filling`/`awaiting_court` with 4
   occupying seats and `now() < start_at`.
2. Sandbox: status `booked`, `reservation_id` stays NULL, event `booked`; go to step 7.
3. `assert_bookable(price_court_id, start_at, end_at)` in a sub-block. If it fails,
   `match_end(id, 'cancelled', 'venue_closed', 'system')`; return.
4. `v_court := match_pick_court(m)`. If found:
   - `set_config('app.match_booking', id, true)`;
   - `insert into reservations (venue_id, court_id, kind, status, start_at, end_at, guest_id,
     guest_name, source, rate_rule_id, price_iqd, created_by_staff_id) values (m.venue_id, v_court,
     'booking', 'confirmed', m.start_at, m.end_at, NULL, 'Open match', case m.organised_by when
     'desk' then 'desk' else 'mobile' end, m.rate_rule_id, m.price_iqd, m.created_by_staff_id)`.
     The price is the stamp (DF-3), whatever the court prices at now. `exclusion_violation` raises
     `SLOT_TAKEN` (it cannot happen under the court locks);
   - reset `app.match_booking` to `''`; update the match to `booked`, `reservation_id`; event
     `booked` (`data {reservation_id, court_id}`).
5. Otherwise, if `match_court_free_firm(…, 1)` (only live non-firm rows, i.e. holds, block):
   status `awaiting_court`, event `awaiting_court` (DF-18).
6. Otherwise `match_end(id, 'bumped', 'bumped', 'system')`; return `bumped`. This is reachable only
   when the trigger's bump was swallowed.
7. Pending requests of the match → `expired` (code `match_full`), their tickets released.
8. Return the status.

The GUC `app.match_booking` stops the reservation trigger from judging the match being booked
against its own new row.

#### 2.8.4 Tickets

**`app.ticket_pick(p_guest_id uuid, p_count int, p_sandbox boolean, p_request_id uuid default
null) returns uuid[]`** (addition). It locks, `order by id for update`, either:
- every `available` ticket of `p_guest_id` with `sandbox = p_sandbox`, and returns the `p_count`
  oldest by `(created_at, id)`. When there are fewer, it raises `NEED_TICKETS` with `detail =
  {"needed":n,"available":k,"buy":n-k}::text` (the `PRICE_CHANGED` detail form, 0242:1396-1398); or
- with `p_request_id`, the request's `reserved` tickets, all of them.

Picking before the seats are inserted is what lets `match_seats_kind` require `ticket_id` without a
deferred check.

**`app.ticket_lock(p_ticket_ids uuid[], p_seat_ids uuid[] default null, p_request_id uuid default
null) returns int`**: locks the ids (`order by id for update`), then:
- with `p_seat_ids` (pairwise), moves `available` or `reserved` → `in_use`: `seat_id` set,
  `request_id` cleared; event `locked`;
- with only `p_request_id`, moves `available` → `reserved`; event `reserved`.

It returns how many moved. A caller that gets fewer than it asked for raises (join and approve
cannot, because `ticket_pick` just locked them; the attended-undo maps it to `SEAT_MARK_LOCKED`).

**`app.ticket_release(p_ticket_ids uuid[], p_code text) returns int`**: `reserved|in_use →
available`; clears `seat_id`/`request_id`; event `released` with `code`. Other states are skipped,
so it is idempotent.

**`app.ticket_forfeit(p_ticket_id uuid, p_seat_id uuid) returns boolean`**: `in_use` on `p_seat_id`,
or `available` → `forfeited`. It sets `forfeited_at = now()`, `forfeited_venue_id` = the seat's
venue, `forfeited_seat_id = p_seat_id`, `seat_id = NULL`; event `forfeited`. Already forfeited by
this seat → true. `reserved`, or in use by another seat → false.

**`app.ticket_restore(p_ticket_id uuid, p_seat_id uuid default null) returns boolean`** (addition):
`forfeited → available`, or `→ in_use` on `p_seat_id`. Clears the three `forfeited_*` columns; event
`restored`.

Every ticket event carries `guest_id`, `venue_id`, `match_id`, `seat_id`, `request_id`, and
`actor_staff_id = auth.uid()` when the caller is staff.

#### 2.8.5 Ending, organiser, events, counts

**`app.match_end(p_match_id uuid, p_status text, p_reason text, p_actor text) returns boolean`**
(the caller holds the mutex; false if the match is already terminal):
- `p_status` in (`cancelled`,`bumped`,`expired`) on a `filling`/`awaiting_court` match:
  - `in` seats → `cancelled` (`match_ended`), their tickets released (code = `p_reason`);
  - pending requests → `expired`, tickets released.
- `cancelled` with `reservation_cancelled` on a `booked` match:
  - `in`, `attended` and `no_show` seats → `cancelled` (`match_ended`). `in` tickets are released;
    `no_show` tickets are restored to `available`;
  - `left_late` seats → `cancelled` (`match_ended`), and their tickets are released, or restored
    if already forfeited. The venue cancelled: nobody loses a ticket. The status change matters:
    a `left_late` seat still holding a released ticket would collide with that ticket's next seat
    on `match_seats_ticket_live`;
  - pending requests expire.
- `cancelled` with `called_off_short` (only from `desk_call_off_short`, after its marks): no seat or
  ticket changes here.
- `no_show` with `all_no_show` (only from `mark_match_seats`): status only.
- Then it sets `status`, `ended_at`, `ended_reason`, `updated_at` and writes one event: type =
  `p_status` (`cancelled`/`bumped`/`expired`/`no_show`), `code = p_reason`, actor `p_actor`.

**`app.match_recompute_organiser(p_match_id uuid) returns boolean`** (filling, awaiting or booked
matches):
1. `organised_by = 'desk' and organiser_id is null`: nothing.
2. The organiser still holds an occupying seat (`account`, or a `desk` seat linked to them):
   nothing.
3. Otherwise the new organiser is the holder of an occupying `account` seat with the earliest
   `joined_at` (seat id breaks ties). Every such seat is a confirmed player, so critic m2 is closed.
   Event `organiser_changed` (`data {from_guest_id, to_guest_id}`).
4. No account holder, but occupying seats remain (desk walk-ins): `organiser_id := NULL`,
   `join_policy := 'open'` (critic m1: the CHECK holds and the match lives on). Pending requests
   expire (code `organiser_gone`); event `organiser_changed` with `to_guest_id: null`.
5. No occupying seat at all: a filling or awaiting match → `match_end(…, 'cancelled', 'empty',
   'system')`. A booked match stays for the desk.

**`app.match_event(p_match_id uuid, p_venue_id uuid, p_type text, p_actor text, p_seat_id uuid
default null, p_request_id uuid default null, p_code text default null, p_data jsonb default
'{}') returns bigint`**: the actor ids come from `auth.uid()` for `guest`/`staff`, NULL for
`system`.

**`app.guest_games_played(p uuid) returns int`**: `attended` seats with `guest_id = p` and `kind in
('account','desk')` in non-sandbox matches, plus `booking` reservations with `guest_id = p` and
status `arrived|completed` (OM-41).

**`app.guest_match_no_shows(p uuid) returns int`**: `no_show` seats with `guest_id = p` in
non-sandbox matches. That includes friend seats, which count on the holder (DF-15), and linked desk
seats. It adds `booking` reservations with `guest_id = p` and status `no_show`. This is the same
number `customer_counts.noShows` shows (DF-12).

**`app.trg_sanitise_match_seat()`** (§2.3.2). `app.match_seat_money` and
`app.court_fee_written_off` are Money's (§1.5).

### 2.9 Guest RPCs (0257)

Rules for all of them:
- `security definer`, `revoke … from public, anon`, `grant execute … to authenticated`.
- The first statement is `match_guest(…)`.
- Every body that writes asserts `set_config('app.venue_id', m.venue_id, true)` (a staff member

- Nothing is queued (DF-11). Start, join, request and approve call
  `assert_not_degraded_for(start_at, venue)` (0210:111); leave, withdraw, remove and cancel do not.

#### 2.9.1 `match_quote(p_venue_id, p_court_id, p_start_at, p_duration_min) → jsonb`

`match_guest(false)`. Refusals: `INVALID_ARGUMENT` (a NULL argument), `COURT_NOT_FOUND` (the court

written. Every other refusal `match_start` would raise from its unlocked checks comes back as
`refusal`, so the sheet can explain before the tap. The candidates are `MATCHES_OFF`,
`BEYOND_HORIZON`, `CLOSED_DATE`, `OUTSIDE_HOURS`, `SLOT_IN_PAST`, `MATCH_TOO_LATE`, `NO_RATE`,
`PHONE_REQUIRED`, `TERMS_REQUIRED`, `MATCH_BANNED`, `GENDER_REQUIRED`, `MATCH_LIMIT_REACHED`,
`SLOT_TAKEN`, `MATCH_SLOT_FULL` (unlocked counts) and `NEED_TICKETS`.

```json
{ "enabled": true, "price_iqd": 40000, "shares_iqd": [10000,10000,10000,10000],
  "fill_deadline_at": "…", "earliest_start_at": "…", "categories": ["open","women"],
  "my_gender": "female", "tickets_available": 1, "ticket_price_iqd": 10000,
  "seats_max": 3, "filling_at_time": 1, "courts_free": 2, "refusal": null }
```

`categories` is `open` plus the caller's own gender, or all three when gender is unset (the start

#### 2.9.2 `match_start(...)` (§1.6 args) → jsonb

`p_friends` is `[{"gender": "female"|"male"|null}]` with 0–2 entries. Gender is required in a
gendered category.

Refusals:
1. `match_guest(true)`: AUTH_REQUIRED, ACCOUNT_REQUIRED, PHONE_REQUIRED, TERMS_REQUIRED,
   MATCH_BANNED, GENDER_REQUIRED.
2. Idempotency: a match with this `idempotency_key` and `organiser_id = caller` returns the same
   JSON with `duplicate:true`. The key under anyone else → `IDEMPOTENCY_CONFLICT`. This is the
   `hold_slot` pattern (0225:96-110), and a lost unique race is caught the same way.
3. `INVALID_ARGUMENT` (detail = the argument): a NULL required argument; an enum outside its list;
   `p_friends` not an array of that shape; `p_quoted_price_iqd` NULL or negative.
4. `MATCH_SEAT_LIMIT`: more than 2 friends (OM-20; the 4th seat is always someone else's).
5. `COURT_NOT_FOUND`: `p_court_id` is not active at `p_venue_id`, or the branch is not in
   `open_venue_ids()`.
6. `MATCHES_OFF`.
7. `INVALID_DURATION`: not in the court's `duration_options`.
8. `BEYOND_HORIZON` (`max_booking_horizon_days`, as 0225:133-139).
9. `CLOSED_DATE` / `OUTSIDE_HOURS` (`assert_bookable`).
10. `SLOT_IN_PAST`.
11. `MATCH_TOO_LATE` when `p_start_at < now() + (match_fill_deadline_minutes + 60) minutes` (OM-43);
    detail = that number of minutes.
12. `DEGRADED_LOCKOUT`.
13. `MATCH_GENDER_MISMATCH`: the caller's gender, or a friend's declared gender, against a `women` or
    `men` category (detail `friend` for a friend; a NULL friend gender in a gendered category is
    `INVALID_ARGUMENT p_friends`).
14. `MATCH_LIMIT_REACHED` (OM-37): the caller already holds an `in` seat in
    `max_filling_matches_per_guest` matches that are `filling` or `awaiting_court`; detail = the cap.
    Counted without a lock, the accepted `HOLD_QUOTA_EXCEEDED` shape (0225:155-167).
15. `[lock]` `match_lock_courts(venue, period)`, then `lock_match_venue(venue)`.
16. `SLOT_TAKEN`: no firm-free court offers the length (`match_court_free_firm(…, 1)` is false).
17. `MATCH_SLOT_FULL` (OM-42): `n` = non-sandbox `filling`/`awaiting_court` matches of the branch
    overlapping the period; refused unless `match_court_free_firm(…, n + 1)`. Detail = `n`. A sandbox
    start is not counted and not checked.
18. `NO_RATE`: `price_slot(p_court_id, …)` finds no rule.
19. `PRICE_CHANGED` when `price_iqd <> p_quoted_price_iqd`; detail `{"quoted_iqd","current_iqd"}`
    (quote = charge, 0242:1394-1400).
20. `NEED_TICKETS` from `ticket_pick(caller, 1 + friends, caller.payment_sandbox)`.

Writes:
- The match: `filling`, `organiser_id` = caller, `organised_by 'guest'`, `sandbox` =
  caller's `payment_sandbox`, `price_court_id = p_court_id`, `shares_iqd = match_shares(price)`,
  `fill_deadline_at = start − deadline minutes`, `share_token = translate(rtrim(encode(
  extensions.gen_random_bytes(16),'base64'),'='),'+/','-_')` (0014:98 source).
- Seat 1 `account` (gender = profile), seats 2.. `friend` (gender as declared), `share_iqd =
  shares_iqd[seat_no]`, `ticket_id` from the pick.
- `ticket_lock(ids, seat_ids)`; event `started` (`data {seats}`).

```json
{ "duplicate": false, "match_id": "…", "status": "filling", "share_token": "…",
  "seats": [{"seat_id":"…","seat_no":1,"kind":"account"}],
  "price_iqd": 40000, "shares_iqd": [10000,10000,10000,10000],
  "fill_deadline_at": "…", "tickets_locked": 1, "tickets_available": 0 }
```

#### 2.9.3 `match_join(p_match_id, p_friends, p_token) → jsonb` (instant, OM-4)

Refusals:
1. `match_guest(true)`.
2. `INVALID_ARGUMENT` (`p_match_id` NULL, `p_friends` shape).
3. `MATCH_SEAT_LIMIT` (more than 2 friends).
4. `MATCH_NOT_FOUND`: unknown, or `match_visibility` is NULL. A sandbox mismatch lands here.
5. `MATCHES_OFF`.
6. `MATCH_APPROVAL_REQUIRED`: `join_policy = 'approve'`.
7. The caller holds an occupying seat (`account`, or a linked `desk` seat): `duplicate:true` with
   the current seats when their count equals `1 + friends`, otherwise `MATCH_ALREADY_IN`.
8. `MATCH_UNAVAILABLE`: a block (either way, organiser or occupying holder), an exclusion (OM-44),
   or a banned organiser. It deliberately does not say which.
9. `MATCH_GENDER_MISMATCH` (caller or a friend).
10. `MATCH_CLOSED`: terminal, or `filling` past `fill_deadline_at`, or `booked` at or after
    `start_at`. `MATCH_FULL`: `awaiting_court`; `filling` with fewer free seat numbers than `1 +
    friends`; `booked` with fewer open seat numbers than that.
11. `MATCH_LIMIT_REACHED` (only when the match is `filling`; a refill is exempt).
12. `DEGRADED_LOCKOUT`.
13. `[lock]` `match_lock(p_match_id)`; re-check 7 and 10.
14. `NEED_TICKETS` (`ticket_pick`).

Writes:
- A filling match: seats take the lowest free `seat_no`.
- A booked match (refill): the seats take the open `seat_no`s in ascending order.
  `replaces_seat_id` is the latest ended seat on that number; a `left_late` one becomes `refilled`
  and its ticket is released (`refilled`), or restored if already forfeited; event `refilled` per
  replaced seat.
- `ticket_lock`; event `joined` (`data {seats, refill}`).
- When a filling match reaches 4 occupying: `match_try_book`.
- The unique index backstop maps `unique_violation` to `MATCH_ALREADY_IN` (critic m12).

```json
{ "duplicate": false, "match_id": "…", "match_status": "filling|awaiting_court|booked|bumped",
  "refill": false, "seats": [{"seat_id":"…","seat_no":3,"kind":"account"}],
  "tickets_locked": 1, "tickets_available": 0 }
```

#### 2.9.6 `match_decide(p_request_id, p_approve) → jsonb`

Refusals:
1. `match_guest(false)`.
2. `INVALID_ARGUMENT` (NULL arguments).
3. `REQUEST_NOT_FOUND`: unknown, or the caller is not a participant of its match. Unknown and
   someone else's read the same (the 0038 #7 rule).
4. `NOT_ORGANISER`: a participant who is not the organiser (after a handover, say).
5. Already `approved` with `p_approve`, or `declined` without it → `duplicate:true`.
6. `REQUEST_CLOSED`.
7. Decline: `[lock]` L1, re-check 4 and 6 (critic m2), then `declined`, tickets released

8. Approve:
   - `MATCH_CLOSED` / `MATCH_FULL` (free or open seats < `seats_requested`).

#### 2.9.7 `match_leave(p_match_id, p_seat_ids) → jsonb`

`p_seat_ids` NULL means all of the caller's `in` seats (account, friend, linked desk) plus their
pending request.

Refusals:
1. `match_guest(false)`.
2. `INVALID_ARGUMENT`.
3. `MATCH_NOT_FOUND`: unknown, or the caller is not a participant.
4. `SEAT_NOT_FOUND`: an id that is not one of the caller's `in` seats in this match.

7. `SEAT_HOLDER_REQUIRED`: the subset leaves the account seat but keeps friends.

With nothing left to leave, it returns `duplicate:true`.

Writes:
- `filling`/`awaiting_court`: seats → `left` (`left`), tickets released (`left`); an awaiting match

- `match_recompute_organiser`.

Returns `{match_id, match_status, left:[{seat_id,status}], request_withdrawn, organiser_changed,

#### 2.9.11 `match_report(...)`, `match_block(...)`, `match_unblock(p_block_id)`

`match_report`: `match_guest(false)` → `INVALID_ARGUMENT` (reason, `p_block` NULL) →
`REPORT_TARGET_INVALID` → a duplicate `(reporter, reported, match)` returns `duplicate:true` →
`RATE_LIMITED` (more than 10 reports by the caller in 24 h).

`REPORT_TARGET_INVALID` covers:
- not exactly one of `p_seat_id`/`p_request_id`;
- a target not in this match;
- the caller is not a participant;
- the target's `guest_id` is NULL (a typed desk seat) or is the caller;
- a request target when the caller is not the organiser.

A friend seat reports its holder. The report is inserted `open`. With `p_block`, a block is added
too (a duplicate is fine). The managers at the branch are told through
`notify_staff(<manager and owner ids at the branch>, 'staff_info', {route:'staff', id:report_id,
title_key:'match_report_new', params:{}}, 'match_report:'||report_id)` inside a `begin … exception
when others then null` (the 0193 stance). Returns `{report_id, duplicate, blocked}`.

`match_block`: the same target rules, with `BLOCK_TARGET_INVALID`; a duplicate pair returns
`duplicate:true`. A block removes nobody from a match they already share. It hides future matches
(§2.8.2) and refuses future joins, requests and approvals between the two (`MATCH_UNAVAILABLE`,
`REQUESTER_INELIGIBLE`). Returns `{block_id, duplicate}`.

`match_unblock`: `match_guest(false)` → `INVALID_ARGUMENT` → deletes the caller's own block →
`{unblocked: true|false}`.

### 2.12 The reservation trigger and the sweep (0259)

#### 2.12.1 `app.trg_reservation_match()`, trigger `reservations_match`

```sql
create trigger reservations_match
  after insert or update of kind, status, court_id, start_at, end_at on reservations
  for each row when (new.kind in ('booking','maintenance'))
  execute function app.trg_reservation_match();
```

It is one trigger for both jobs, so the lock gate expands one body per reservation write. The WHEN
clause keeps every hold write (`hold_slot`, `expire_stale_holds`, `release_hold`) out. An INSERT
trigger's WHEN cannot read OLD, so the "just became firm / moved" test is in the body.

**Part A, cascade** (UPDATE only; errors are not swallowed):
1. `select … from matches where reservation_id = new.id` (unique index). None → go to part B.
2. `set_config('app.venue_id', new.venue_id, true)`; `lock_match_venue(new.venue_id)`; re-read.
   Status not `booked` → go to part B (call-off, all-no-show and sandbox already wrote the match).
3. Status changed:
   - → `cancelled`: `match_end(id,'cancelled','reservation_cancelled', case new.cancelled_by when
     'staff' then 'staff' else 'system' end)`.
   - → `no_show`: raise `MATCH_MARK_SEATS` (the only legitimate path ends the match first).
   - → `completed`: `in` seats → `attended` (`marked_at now()`, `marked_by_staff_id` = the caller if
     staff), tickets released; unrefilled `left_late` tickets still `in_use` → forfeited; match →
     `played`; events `seat_attended` (code `auto`) and `played`.
   - → `arrived`: nothing.
4. `court_id`, `start_at` or `end_at` changed: copy `start_at`, `end_at`, `duration_min` to the
   match; event `moved` (`data {court_id}`). The shares stay stamped (DF-4). `matches_deadline` does
   not apply to a booked match.

A raise aborts the desk operation with a mapped code, never a half-done cancel (critic M4).

**Part B, bump** (swallowed; the sweep is the backstop):
1. Return unless `new.status in ('confirmed','arrived')` and (INSERT, or `old.kind` differs, or
   `old.status not in ('confirmed','arrived')`, or court or time changed). Holds and `booking/
   pending` rows never bump (OM-13, critic M11).
2. Cheap pre-check, unlocked: a non-sandbox match at `new.venue_id`, status `filling|awaiting_court`,
   `period && new.period`, `id <> nullif(current_setting('app.match_booking', true), '')::uuid`.
   None → return.
3. `begin` `set_config('app.venue_id', …)`; `lock_match_venue(new.venue_id)`. Then, in a **new
   statement** (fresh snapshot), loop over those matches in id order: `if not
   match_court_free_firm(m.venue_id, m.period, m.duration_min, 1) then match_end(m.id, 'bumped',
   'bumped', 'system')`. `exception when others then raise warning 'match bump deferred: %',
   sqlerrm; end`.

Coverage: desk bookings, blocks and series; event blocks; guest confirm; the deposit confirm and
re-create; move and extend into the period; another match's booking (the GUC excludes only the
match being booked). Two filling matches with one firm-free court: neither is bumped until one books;
then the other is.

#### 2.12.2 `app.match_sweep(p_venue_id uuid default null) returns jsonb` (service role)

It works in three phases.

**Phase 1, find work (no locks).** List the active venues (or `p_venue_id`) that have any of:
- a `filling` match past its deadline or inside its warning window;
- an `awaiting_court` match;
- a filling/awaiting match with a deleted or banned holder, or no longer fitting (no active court
  for its length, a failed `assert_bookable`, a closed branch);
- a `booked` match before start with an `in` seat of a deleted holder;
- a pending request past its cutoff;
- a `booked` match at or past `start_at` with a `left_late` seat whose ticket is `in_use`;
- a `booked` match past `end_at + 3 h` (sandbox: `end_at`).

The list starts at a rotating offset, `(floor(extract(epoch from now())/30))::int % count`, so no
branch is always last.

**Phase 2, per venue:**
- The first venue locks by blocking: `match_lock_courts(v, tstzrange(min(start_at), max(end_at)))`
  over its due matches, then `lock_match_venue(v)`.
- Every later venue: `app.try_lock_match_venue(v)` (addition) = `pg_try_advisory_xact_lock` on each
  active court key (id order, the same key expression as 0042:56), then on the mutex key. Any false
  → skip the venue this run (`venues_skipped`). It never waits and never expires holds.
- Then, per match, each in its own `begin … exception when others then v_errors := v_errors + 1;
  raise warning …; end` (one match per block), at most 200 matches per run:
  1. **Awaiting:** `now() ≥ start_at` → `match_end(…,'expired','no_court','system')`. Else, unless
     `is_degraded(v)` with the start inside the protected horizon → `match_try_book`.
  2. **Fit backstop** (filling and awaiting):
     - the branch not in `open_venue_ids()`, or `assert_bookable` fails → `cancelled`
       (`venue_closed`);
     - no active court offers the length → `bumped` (`no_court`);
     - no firm-free court → `bumped` (`bumped`).
  3. **Deadline:** `filling` and `now() ≥ fill_deadline_at` → `expired` (`deadline`).
  4. **Warning:** `filling`, `now() ≥ fill_deadline_at − 30 min`, `deadline_warned_at` NULL → event
     `deadline_warning`, stamp.
  5. **Requests:** pending on a match past its deadline (filling), past `start_at` (booked), or
     ended → `expired`, tickets released.
  6. **Deleted or banned holders** (filling/awaiting):
     - deleted: seats → `left` (`account_deleted`), requests → `withdrawn`;
     - banned: seats → `removed` (`banned`), requests → `expired` (code `banned`);
     - tickets released; `match_recompute_organiser`.
     A deleted holder in a booked match before start: seats → `left_late` (`account_deleted`).
  7. **Start forfeits:** `booked`, `now() ≥ start_at`: every `left_late` seat whose `seat_no` has no
     occupying seat and whose ticket is `in_use` → `ticket_forfeit` (code `late_leave`).
  8. **Auto-attend:** `booked` and `now() ≥ end_at + 3 h` (sandbox: `end_at`): `in` seats →
     `attended` (code `auto`), tickets released; match → `played`. The booking itself is left to the
     desk. Marks can still be corrected inside the §2.10.8 window.

**Phase 3, chain-wide:** every purchase whose tickets include an `available` one owned by a deleted
profile, and none `reserved`/`in_use`, gets Money's `ticket_refund_purchase(payment_id,
'account_deleted')`. The ticket rows are locked `for update skip locked`, so a busy purchase waits
for the next run.

Every step selects only rows that still need the change, and every change is a one-way status or a
stamp. A second run in the same second therefore does nothing (idempotent). It returns:

```json
{ "venues_swept":1,"venues_skipped":0,"booked":0,"awaiting_expired":0,"bumped":0,"expired":0,
  "cancelled":0,"warned":0,"requests_expired":0,"left_deleted":0,"removed_banned":0,
  "forfeited":0,"auto_attended":0,"refunds_started":0,"errors":0 }
```

**Cron:** `tp_match_sweep`, `'30 seconds'` with the per-minute fallback, in the guarded DO block of
0242:1811-1822; command `select app.match_sweep();`. After the hosted push, check that `cron.job`
has the row (`packages/db/CLAUDE.md`, "after a hosted push").

### 2.15 Situations we must survive

| # | Situation | What happens |
| --- | --- | --- |
| 1 | The 3rd and 4th joiners of a 2/4 match tap in the same second | Both take `match_lock`. The first takes seat 3; the second takes seat 4 and books. The unique occupying `(match_id, seat_no)` index is the backstop. |
| 2 | Two players race for the last seat (4th, or a booked refill) | Serialised by the courts and mutex. The loser's re-check under the lock → `MATCH_FULL`. No ticket moves for them. |
| 3 | A group books the last free court while the match is at 3/4 | The trigger's bump → `bumped`, every ticket released, pending requests expired. |
| 4 | A guest's hold is on the last court when the 4th joins | `awaiting_court` (DF-18). The hold confirms → the trigger bumps it. The hold lapses → the next sweep run of that branch books it. |
| 5 | A hold lands on the last court while the match is at 3/4 | Nothing: holds never bump (OM-13). |
| 6 | Two tills book courts A and B (the last two) at once | Both triggers take the mutex. The second's check runs in a new statement and sees A committed → one bump, exactly once. A two-connection test covers it. |
| 7 | The desk books the last court while the 4th player is joining | Whoever holds the court locks first wins. Desk first: the match is bumped, and the join re-reads under L2 → `MATCH_CLOSED`. Join first: the match is booked (firm), and the desk gets `SLOT_TAKEN` only if it picked that same court. |
| 8 | Two filling matches, one free court | OM-42 refuses the second start (`MATCH_SLOT_FULL`). If courts were lost later, the first to fill books and the trigger bumps the other. |

### Conflicts with §1

1. **0252 ownership.** §1.1 gives 0252 to Guest; this brief asks DB to specify it. There is no real
   conflict: §2.4 is the contract, and Guest writes the file to it. If Guest has already drafted
   different split or trigger rules, §2.4 wins because every match read depends on it.
2. **`notify_staff` has no owner in §1.8.** Its title keys are a closed list in the body
   (0193:46-55), so `match_report_new` cannot be sent without a re-issue. Fix: DB re-issues it in
   0257 (above). Guest deploys `staff-push.json` and `send-push` before that push.
3. **No file owns the guest push fan-out.** §1.1 has no ordinal for the function or trigger that
   turns `match_events` into `notification_outbox` rows. Fix: Guest adds it as its own section of
   0257 (the table exists from 0254, and send-push is deployed before 0251). Otherwise §1.1 gains
   an ordinal after 0261.
4. **`ticket_lock(uuid[], ...)` cannot both pick and lock.** A seat must name its ticket
   (`match_seats_kind`) and a ticket its seat (`match_tickets_in_use`). Fix: the §1.5 name keeps the
   "set state for these ids" half, and a new `ticket_pick` does the locking pick first (above).
5. **§1.4 "The walker learns app.lock_match_venue"** is not enough on its own. The reservation
   trigger re-takes the mutex under every L2 body, and the gate would read that as `match_tickets →
   match_venue_advisory`. Fix: the gate emits `match_venue_advisory` once per sequence (§2.7). That
   is sound because a blocking body only ever holds one branch's mutex.
6. **§1.4 does not cover the sweep across branches.** Tickets are chain-wide, so a sweep that took
   branch B's courts after locking tickets at branch A could deadlock with a join at B. Fix: after
   the first branch, the sweep only try-locks and skips on failure (§2.12.2).

### Open technical questions

1. **`awaiting_court` end.** This design waits until `start_at`, then expires as `no_court`. The
   alternative is to expire at the fill deadline like `filling`. DF-18 does not say.
2. **Auto-attend at `end_at + 3 h`.** Unmarked seats become `attended`: the ticket is released and
   the share owed. The alternative is to leave them locked until the desk marks. That keeps
   tickets frozen whenever the desk forgets.
3. **Corrections after a ticket was reused.** `attended → no_show` is refused (`ticket_used`) rather
   than forfeiting another available ticket of the same player.
4. **The ban is chain-wide.** A manager at any branch bans or lifts for every branch. A per-branch
   ban would need a table instead of `customer_flags`.
5. **Name rules.** The prefix list, three-token `Abd al …`, and dropping a non-article leading
   `ال` (`الياس` → `ي`) all need client review. Email-local-part names (0069) show as they are.
6. **Anti-abuse constants.** 5 pending requests, 12 messages per match, 10 reports a day, 8-day
   guest windows, 3-day desk windows.
7. **Removal after start.** Only `staff_error`/`duplicate`; everything else is an attendance mark.
8. **Desk refill until `end_at`, and a guest refill until `start_at`.**
9. **`match_invite` gives no oracle.** An unknown token answers `closed`, and the web page cannot
   tell "gone" from "never existed".
10. **The sweep's fairness.** With several branches under load, a branch that is try-locked and
    busy can be skipped for several runs. The rotating start makes it the blocking branch within N
    runs; it is visible as `venues_skipped`.
11. **The gender store category.** `'Other personal info'`: Apple "Other Data Types" versus Google
    "Personal info → Other info" is UNVERIFIED; the Guest lane owns the store forms.
