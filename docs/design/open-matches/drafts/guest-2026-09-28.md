## 4. Guest app, web, push, links, legal (lane Guest)

This lane builds everything a guest touches: the phone (`apps/mobile`), the web invite page
(`apps/web`), the guest push family, universal links, names and gender, and the store and legal
copy. It owns migrations **0251** and **0252**, writes the bodies of two internal functions that
ship in DB's 0256 (§4.12.3), and adds one title key to DB's 0257 re-issue of `notify_staff`.
Everything else it reads is built by DB (§2) and Money (§3). §4.2 lists the fields the clients
read: those lanes may add fields, but may not rename these.

Paths are relative to the repo root. `NNNN:line` is a migration. Code facts were checked on
2026-09-28 against `fa86fe09`.

Four rules bind every item below:
- Every match write is online-only and fails now (DF-11).
- Nothing under the `['match']` query root is written to disk (§1.11).
- No name reaches a lock screen (OM-31) or the web (DF-9).
- All Arabic here is a draft, marked **DRAFT-AR**, and goes on the client review list.

### 4.1 The guest's model

| Moment | Tickets | Money | The guest reads |
|---|---|---|---|
| Buy 1–3 (Qi, `ticket-begin`) | + N `available` | N × price, online | "2 tickets ready" |
| Start, or join an instant match | `available → in_use`, one per seat (friends' seats use the holder's) | none | You're in |
| Ask to join (approve mode) | `available → reserved` | none | Request sent |
| Approved | `reserved → in_use`, seated at once | none | You're in |
| Declined / withdrawn / request expired | `reserved → available` | none | Tickets back |
| Leave while filling, removed by the organiser (OM-44), cancelled, bumped, expired, closed | `→ available` | none | Tickets back |
| Leave after booking (`left_late`) | stays `in_use` | none | Ticket held until someone takes your seat |
| That seat refilled | `→ available` | none | Ticket back |
| Start comes with no refill | `→ forfeited` | none | Ticket lost |
| Attended | `→ available` | full `share_iqd` at the desk | Played |
| No-show | `→ forfeited` | share written off | Ticket lost |
| Called off short (OM-47) | attended `→ available`, no-show `→ forfeited` | nobody pays | Called off |
| Manager cash-out at the desk | unused tickets of one purchase `→ cashed_out` | one Qi refund | Refunded |
| Account deleted (DF-20) | unused tickets refunded | Qi refund | nothing (the account is gone) |

A ticket is not the share. The guest keeps paying the share at the desk; the ticket is the promise
to turn up. The copy says so everywhere money is mentioned (§4.4, §4.7, §4.17).

### 4.2 Server shapes the clients read

DB (§2) and Money (§3) own the bodies and the refusal order. The clients parse defensively, as
`parseDepositStatus` already does (`apps/mobile/src/features/deposit/logic.ts:195-238`): an unknown
enum value falls back and never throws. The phone never computes a price, a share, a ticket count
it acts on, or a permission. It renders `share_iqd`, the wallet counts and `me.can`. Seat and
request values are the §1.3 vocabularies verbatim.

**`match_slots(p_venue_id, p_from, p_to)`** (anon and authenticated, `publicByDesign`)
```json
[{ "start_at": "…", "end_at": "…", "category": "open|women|men",
   "join_policy": "open|approve", "seats_left": 1, "mine": false }]
```
- Covers public `filling` matches at an open branch with `matches_enabled`, `start_at` in
  `[p_from, p_to)`. A window over 8 days gives `INVALID_ARGUMENT`.
- Anon callers see every category: DF-10 treats an unknown gender as "sees both".
- A signed-in caller gets the DF-10 and block filters.
- `mine` is always false for anon.
- No ids, names or price.

**`match_invite(p_token)`** (anon and authenticated, `publicByDesign`)
```json
{ "status": "open|full|closed", "start_at": "…", "end_at": "…", "timezone": "Asia/Baghdad",
  "category": "open|women|men", "join_policy": "open|approve", "seats_left": 2,
  "venue": { "name_en": "…", "name_ar": "…" } }
```
- `closed` carries no other field.
- A NULL, malformed or unknown token answers `closed` and never raises, so it cannot be used as an
  oracle.
- `full` means four occupying seats and no open `left_late` seat.
- No ids, names or price (DF-9).

**`open_matches(p_venue_id, p_from, p_to)`**
```json
{ "banned": false,
  "matches": [{ "id": "…", "start_at": "…", "end_at": "…", "category": "…", "join_policy": "…",
                "status": "filling|booked", "seats_left": 1, "share_iqd": 10000,
                "fill_deadline_at": "…", "mine": "seated|requested|null" }] }
```
- `booked` rows appear only while a `left_late` seat is open before `start_at`.
- No names; names appear only on the detail screen.
- A banned caller gets `banned: true` and an empty list, and the list renders the ban notice
  (§4.6).

**`match_detail(p_match_id, p_token)`**
```jsonc
{ "id", "venue_id", "status", "ended_reason", "start_at", "end_at", "duration_min",
  "category", "visibility", "join_policy", "price_iqd", "fill_deadline_at",
  "seats_taken", "seats_total": 4, "court_id": null /* booked only */,
  "organiser": { "name", "former", "is_me" } | null,
  "seats": [{ "seat_id", "seat_no", "kind", "status", "name", "former", "holder_seat_no", "is_me", "is_mine", "share_iqd" }],
  "me": { "role": "organiser|player|requester|viewer",
          "seats": [{ "seat_id", "seat_no", "kind", "status", "end_reason", "share_iqd", "request_id", "ticket_status" }],
          "request": { "id", "status", "seats_requested" } | null,
          "excluded": false,                  /* OM-44: removed by the organiser, no rejoin */
          "refusal": null | "<CODE>",         /* what a join or request would raise now, tickets aside */
          "can": { "join", "request", "withdraw", "leave", "cancel", "remove", "decide", "message", "report", "block", "share" } },
  "requests": [{ "request_id", "name", "former", "seats_requested", "games_played", "no_shows", "created_at" }], /* organiser; pending only */
  "messages": [{ "code", "seat_no", "name", "former", "is_me", "at" }],   /* participants; last 20 */
  "share_token": null | "<22 chars>",                                   /* participants only */
  "server_now": "…" }
```
- `seats[]` lists the occupying seats plus open `left_late` seats. `name` follows §4.3.2.
- `holder_seat_no` is set on a friend seat.
- Phones never appear.
- `me.refusal` never carries `NEED_TICKETS`. The phone reads tickets from the wallet (§4.4).

**`my_matches(p_scope)`**, where `'upcoming'` means not yet ended plus anything ended in the last
24 hours, and `'past'` is the rest. Limit 100.
```json
[{ "match_id", "venue_id", "status", "ended_reason", "start_at", "end_at", "category",
   "join_policy", "visibility", "seats_taken", "court_id", "fill_deadline_at", "is_organiser",
   "my_seats": [{ "seat_id", "seat_no", "kind", "status", "end_reason", "share_iqd", "request_id", "ticket_status" }],
   "request": { "id", "status", "seats_requested", "decided_at" } | null }]
```

**`my_tickets()`** (Money, 0255)
```json
{ "price_iqd": 10000, "available": 2, "reserved": 0, "in_use": 1, "sandbox": false,
  "tickets": [{ "id", "status", "price_iqd", "bought_at", "purchase_payment_id",
                "match": { "id", "start_at", "venue_id", "status" } | null,
                "forfeited_at", "cashed_out_at" }] }
```
- `price_iqd` is today's `platform_settings.match_ticket_price_iqd`.
- `tickets` holds every non-terminal ticket plus the last 20 terminal ones.

**`my_match_blocks()`**: `[{ "block_id", "name", "former", "created_at" }]`.

**`match_quote(p_venue_id, p_court_id, p_start_at, p_duration_min)`**:
`{ "price_iqd", "shares_iqd": [4 ints], "fill_deadline_at", "duration_min" }`.

**Write results.** The phone reads only `match_id` from `match_start` and `request_id` from
`match_request`. After every other write it refetches `match_detail`, `my_matches` and
`my_tickets`, so their return shapes are free for §2.

**`ticket-begin`** (Money, edge, `verify_jwt = true`)
- Request: `POST { "count": 1..3, "locale": "en"|"ar" }`.
- 200: `{ request_id, form_url, amount_iqd, deadline_at, status: "pending" }`, the shape
  `deposit-begin` returns (`docs/design/payments/build-contracts-2026-09-27.md` §3).
- Errors come as `{ "error": "CODE" }` and map through §4.14.

**`deposit_status` for a ticket** (Money, 0255) is the payments contract §2.2 JSON, plus:
- `purpose: "deposit"|"ticket"`;
- `ticket_count` (1..3; null for a deposit).

For a ticket, `reservation` is null, `hold_live` is false and `deposit_mode` is `off`.

#### 4.3.1 Migration `0252_profile_names_gender`

The file opens with `set lock_timeout = '3s'; set statement_timeout = '60s';` and uses

**Columns** (§1.2):

- `gender_set_at timestamptz`

**CHECKs.** Each is added NOT VALID, then validated inside a guard that tests both `conname` and

- `profiles_given_name_len`: `given_name is null or char_length(given_name) between 1 and 39`.
- `profiles_family_name_len`: `family_name is null or char_length(family_name) between 1 and 39`.

- `profiles_gender_set_by_values`: `gender_set_by is null or gender_set_by in ('guest','staff')`.

The two 39s keep `concat_ws(' ', given, family)` within the 0116 limit of 80
(`profiles_full_name_len`, 0116:98-116).

**`app.split_person_name(p_name text) returns text[]`.** Internal and immutable; returns
`{given, family}`.
- Trim, collapse whitespace, split on spaces.
- `given` is the first token. When that token is a compound prefix (`عبد`, `أبو`, `ابو`, `Abd`,
  `Abdul`, `Abu`, `Abo`, case-folded) and a second token exists, the two tokens join
  (`عبد الله`).
- `family` is the remaining tokens, or NULL when there are none.
- Each part is `left(…, 39)`, and an empty part becomes NULL.
- PROPOSAL: the prefix list and the father's-name reading are accepted under OM-26.

**`app.trg_sanitise_profile`** is re-issued from 0080:130-140. It adds
`new.given_name := nullif(app.safe_line(new.given_name), '')`, and the same for `family_name`. The
trigger `profiles_sanitise` becomes
`before insert or update of full_name, phone, given_name, family_name` (from 0080:144-147).

**`app.trg_profile_names()`** (security definer, internal) backs the new trigger
`profiles_sync_names`: `before insert or update of full_name, given_name, family_name,
deleted_at, gender`. The name sorts after `profiles_sanitise`, so it always sees sanitised
values. It applies the first matching rule:

| Situation | Result |
|---|---|
| `new.deleted_at is not null` | `given_name`, `family_name`, `gender`, `gender_set_at` and `gender_set_by` all become NULL. This is the 0077 tombstone UPDATE (0077:187-192), so the erasure proof holds from 0252, before 0260 re-issues the deletion. |
| `current_setting('app.profile_names_backfill', true) = 'on'` | nothing (the backfill below) |
| INSERT with `given_name` set | `full_name := concat_ws(' ', given_name, family_name)` |
| INSERT without `given_name` | `(given_name, family_name) := split_person_name(full_name)` |
| UPDATE where `given_name` or `family_name` is distinct from old | `full_name := concat_ws(' ', given_name, family_name)` |
| UPDATE where only `full_name` changed (old builds, `desk_register_customer` 0065:580-585, staff edits) | parts re-split from `full_name` |
| `gender` changed and `gender_set_at` did not | `gender_set_at := now()` |

**Backfill.** Under `set local app.profile_names_backfill = 'on'`, set
`(given_name, family_name) := split_person_name(full_name)` where `deleted_at is null` and
`given_name is null`. The flag stops the trigger from rewriting `full_name`. Without it, a family
part truncated to 39 characters would shorten a stored name. Profiles are a few thousand rows,
well inside the 60 s statement timeout.

**`app.handle_new_user`** is re-issued from its latest body (0069:204-244; `$$` becomes

#### 4.3.2 How a player is named to other players

The body is DB's `match_display_name(uuid) returns jsonb` (§1.5). The rule belongs to this lane:
- A deleted account gives `{ "name": null, "former": true }`, rendered as "Former player"
  (OM-26). A name like "Deleted a." never appears.
- `first` is `given_name`, falling back to the first word of `full_name`.
- The initial is the first letter of `family_name` after dropping any of these, then uppercased
  for Latin script:
  - a leading attached `ال` (الحسيني → ح);
  - a leading separate `آل` or `ال` word (آل ياسين → ي);
  - a leading `al-`, `el-`, `al ` or `el ` (Al-Hassan → H).
- `name` is `"<first> <initial>."`, or `first` alone when there is no family name: "Ahmed K.",
  "أحمد ح.".
- A desk seat's typed `guest_name` goes through `split_person_name`, then the same rule. A desk
  seat with no name renders as "Player".
- A friend seat carries its holder's name plus `holder_seat_no`, and the phone renders
  "{name} +1" (§4.16).

#### 4.4.3 `NEED_TICKETS` → buy → continue the same action

**Pre-check.** On `match-new` and the detail action card, when the wallet has loaded,
`available < seats wanted` swaps the primary for "Buy {missing} and join" (or "…and ask", "…and
start"). A tap goes straight to the purchase and skips a doomed RPC. The server stays
authoritative: a `NEED_TICKETS` refusal from `match_start`, `match_join` or `match_request` takes
the same path after a wallet refetch.

**Continuation** (`features/matches/continuation.ts`, pure plus a thin hook):
```ts
type TicketContinuation = { savedAt: string } & (
  | { kind: 'join';    matchId: string; token: string | null; friends: FriendSeat[] }
  | { kind: 'request'; matchId: string; token: string | null; friends: FriendSeat[] }
  | { kind: 'start';   venueId: string; courtId: string; startAt: string; durationMin: number;
                       category: 'open'|'women'|'men'; visibility: 'public'|'link';
                       joinPolicy: 'open'|'approve'; friends: FriendSeat[];
                       quotedPriceIqd: number; idempotencyKey: string });
type FriendSeat = { gender: 'female' | 'male' | null };   // the p_friends element, 0..2 of them
```
1. The screen that hit the shortage calls `setTicketContinuation(c)` (in memory) and pushes
   `/tickets?buy=<missing>&for=<kind>`, with `missing` clamped to 1..3. Backing out of `tickets`
   clears it.
2. `useStartTicketPurchase` writes it into the persisted pointer as `after`, so it survives the
   app being killed on Qi's page. The key is the one SEC-16 already purges (`purgeKeys.ts:63-65`).
3. `pay/status` reaches `ticketsBought` (§4.4.4). If `after` is present, `claimContinuation(ref)`
   is true (once per ref per app life), and `now − savedAt ≤ 30 min`, it runs the same RPC with
   the same arguments. For `start` that includes the same `p_idempotency_key`: a refused
   `match_start` rolled back its `claim_replay` row (0049:68-92), so the key is unspent.
4. **Success:**
   - join: `router.replace('/match/[id]')` + toast "You're in";
   - request: toast "Request sent";
   - start: toast "Your match is open. Share the link to fill it." (on the new id).
5. **Refusal:** toast `mapErrorToKey(err)` and land on the match (or, for `start`, the Book sheet
   through `requestBookingSheet()`). The tickets stay in the wallet, and the copy says so ("Your
   tickets are in your wallet").
6. **Stale** (over 30 min, or already claimed): no automatic call. `pay/status` shows "Back to the
   match" (`pay-status.back-to-match`) or "Start the match" (`pay-status.continue`), and a tap runs
   the same continuation.

### 4.5 The Book tab

#### 4.12.3 Queueing (bodies written here, shipped in DB's 0256)

**`app.match_notify(p_match_id uuid, p_recipients uuid[], p_title_key text, p_params jsonb default '{}', p_actor uuid default null, p_scheduled_for timestamptz default null, p_dedupe text default null) returns int`**
- Internal: revoked from public, anon and authenticated.
- The kind comes from `p_title_key` through the JSON map (a copy inside the body, compared by
  test), so kind and key can never disagree.
- `INVALID_ARGUMENT` when:
  - the key is unknown (hint `title_key`);
  - a params key falls outside `seats_taken`, `seats_total` or `minutes`, or a value is not an
    integer (hint `params`);
  - `p_match_id` is null for any key but `tickets_refunded`.
- Builds `{route, id, title_key, params, dedupe?}` with route `tickets` for `tickets_refunded` and
  `match` for every other key.
- Inserts one `notification_outbox` row per distinct recipient that has a profile with `deleted_at
  is null` and is not `p_actor`. It queues even with no push token, as `notify_staff` does
  (0160:86-91); send-push closes the row `NO_PUSH_TOKEN`.
- Unless `p_scheduled_for` is set, it then calls `perform app.push_nudge()`.
- The insert block is wrapped `begin … exception when others then return 0; end`, so a push can
  never fail a match write (0193:23-28). Validation happens before the wrapper, so tests catch a
  bad call.

**`app.match_sync_reminders(p_match_id uuid) returns void`**
- Internal. It deletes unsent `match_reminder` rows whose `payload->>'id'` is this match.
- When the match is `booked` and `start_at − 3 h > now()`, it queues `reminder_3h` for the holders,
  scheduled at `start_at − 3 h`.
- DB calls it after every change that can alter the answer: booked, moved, a seat change on a
  booked match, ended.
- A match booked inside the last 3 hours gets no reminder, because `match_booked` has just
  arrived. The booking family's upkeep (0090:176-205) is the precedent.

**`lib/queryClient.ts`:**
- `shouldDehydrateQuery` (`:188-193`) adds `query.queryKey[0] !== 'match'`. Match reads carry
  other guests' names, and a wallet read back from disk would be shown before it is re-checked.
- `setMutationDefaults(['match','mutation'], {networkMode:'always', retry: (n, e) => n < 1 && isRetriable(e)})`
  beside `:137-159`: run now or fail now (DF-11). One retry is safe, because every match write is
  keyed or state-idempotent.
- `setQueryDefaults(['match','slots'], {retry: (n, e) => n < 1 && isTransportError(e)})`: the Book
  sheet fails fast before the migrations land, for the same reason as `['deposit','quote']`
  (`:160-162`).

**Idempotency** (`lib/idempotency.ts`):
- `matchIdemKey()` returns `MOBILE:match.start:<ulid>`.
- `matchIntentKey(intent)` and `clearMatchIntentKey(intent)` follow the memo rule at `:44-57`.
  The only intent is `start:<venueId>|<courtId>|<startAt>|<durationMin>`, since `match_start` is
  the only guest match RPC with `p_idempotency_key` (§1.6).
- The key is kept across the refusals the guest fixes and retries: `NEED_TICKETS`,
  `GENDER_REQUIRED`, `PHONE_REQUIRED`, `TERMS_REQUIRED` and `PRICE_CHANGED`. It is cleared on
  success or any other refusal.
- Every other write is state-idempotent on the server, through the unique occupying seat, unique
  pending request, unique block pair and unique report, and takes no key.

**Persistence and purge.**
- No new AsyncStorage key. The ticket continuation rides in `tp.pendingPayment.<uid>`, already on

- `pendingJoin` and the pre-payment continuation are memory only.
- `clearAllCaches` (`queryClient.ts:204-212`) wipes `['match']` on sign-out.

**Grammatical gender (AR)** (d5 §6.2):
1. A third person ("a player", "the organiser", "former player") takes the feminine form in a

   the same text so parity holds. `byCategory(category, key)` picks one.
2. Text addressed to the reader avoids gendered verbs and adjectives. It uses verbal nouns
   (حجز، بدء، الانضمام), passives (أُرسل، أُلغيت), "يمكنك / يلزم / يُرجى + noun", unvocalised
   past tense (غادرت، سحبت) and possessive suffixes, which read the same for both.
3. Where a form cannot be avoided (the `organiser_handover` push), it follows the reader's
   `profiles.gender`: send-push reads it, and in the app it comes from `useOwnProfile`. NULL is
   treated as masculine.
