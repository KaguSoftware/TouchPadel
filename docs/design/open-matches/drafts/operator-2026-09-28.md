## 5. Operator (lane Operator)

The staff app (`apps/operator`) side of open matches: the calendar, the Today board, the new-booking
dialog, a match screen, the Players panel on a booked match, the customer record, the settings
panel, the Ops reports queue, day close and the Courts report, plus the assistant map. This lane
writes no SQL. It calls the §1.7 staff RPCs and the §1.8 re-issued reads, and it names below the
keys it reads from each. Code facts were checked on `fa86fe09` (latest migration 0248).
`op/` is `apps/operator/src/`.

Ground rules for every file in this lane:
- Every match write is a direct `appRpc('<name>', …)` call with the literal RPC name (DF-11). There
  is no queued mutation type, so the six-copy contract (`apps/operator/CLAUDE.md` "Writes") is
  untouched. The literal name matters: the assistant map finds operator callers with the regex
  `(?:appRpc|\.rpc)\(\s*'name'` (`packages/db/scripts/build-assistant-map.mjs:516`), so no
  `depositRpc`-style wrapper (`op/features/deposits/depositApi.ts:22`). The operator build lands
  after the migrations, so `types.gen.ts` already names every RPC.
- A non-idempotent write carries `p_idempotency_key` minted once per dialog as
  `` `match.<action>:${crypto.randomUUID()}` `` and re-minted after a success (the CourtBlock
  precedent, `op/features/desk/CourtBlock.tsx:296,320`).
- The server is the wall. Buttons follow `CAPABILITY_ROLES` for the screen and the `can` object of
  `desk_match_detail` for each row. No inline role check.
- Nothing on a staff screen computes money. The client only sums the server's `owed_iqd` over the
  seats picked for one payment, and the server re-checks that sum (`SEAT_OWED_CHANGED`).

### 5.1 What the decisions force on the staff side

| Decision | Staff side |
| --- | --- |
| OM-13, OM-12 | A filling match has no reservation, so no court column shows it. It shows in the Today group, a calendar strip and its own screen. A desk booking or block that takes the last free court bumps it; the new-booking dialog warns (client mirror), and the server decides. |
| OM-45, OM-47 | Attendance is per seat. `attended`: the ticket comes back and the player owes their full share at the desk. `no_show`: the ticket is lost and the share is written off. Call off short cancels the booking; nobody pays. |
| OM-29, OM-30 | Desk seats (start for a customer, walk-in) need no ticket and bypass approval. |
| OM-20, OM-39 | Up to 3 seats per player. In a women's or men's match every seat carries the category's gender; the desk vouches. |
| OM-26 | Staff see full names and phones. The row also shows what players see ("Players see: Sara K."). |
| OM-27, OM-48 | Ban, report review and ticket cash-out are manager or owner actions. |
| OM-43, OM-42 | The start dialog refuses a start later than `now + fill deadline + 60 min` would allow, and says when enough matches already fill that time. |
| DF-4 | A move or extend of a booked match re-prices the booking. The shares stay as stamped; the difference is a booking-level line. |
| DF-11 | Every match control is disabled offline with a reason. The booking-level bill still takes money through the queued `tab.open`/`tab.settle`; Assign links it to players later. |
| DF-12, DF-15 | The record's no-show count includes seat no-shows; a friend seat's no-show counts on the holder. |
| DF-16 | Café items never go on a match booking. The desk hides "Add cafe bill" and "Charge on till" on a match booking. |

### Conflicts with §1

1. **`match_seat_write_off` cannot be called PIN-gated with its §1.7 signature.** `appRpc` proves
   the PIN only when `args.p_pin` is a string, then passes every argument to the RPC
   (`op/lib/appRpc.ts:69-79`). The RPC spends the grant with `app.consume_pin_grant(p_device_id)`
   (0156:446), as `deposit_refund_manual(p_payment_id, p_pin, p_note, p_device_id)` does
   (0242:1208-1236). A signature without `p_pin` fails to resolve in PostgREST, and without
   `p_device_id` it cannot name the grant's device. **Fix:** `match_seat_write_off(p_seat_id uuid,
   p_reason text, p_pin text, p_device_id text default null)`, and `PIN_GATED_RPCS`
   (`packages/core/src/schemas/mutations.ts:49-57`) gains `match_seat_write_off` in the same commit.
2. **OM-47's walk-in in place of a no-show is impossible under §1.2's seat index.** The unique
   occupying `(match_id, seat_no)` covers `in`, `attended` and `no_show`. After a no-show is marked,
   all four seat numbers stay occupied, so `desk_add_seat` has no seat to fill. **Fix:** the
   `(match_id, seat_no)` uniqueness covers `in` and `attended` only (the `(match_id, guest_id)`
   account index keeps all three). `desk_add_seat` after the start fills a `no_show` seat's number
   with `replaces_seat_id` = that seat. The no-show keeps its row, status, forfeit and DF-12 count.
   The replacement owes that seat's `share_iqd`, and `court_fee_written_off`'s cap on
   `price − court_fee_paid` already stops the share being counted as written off and paid at once.
   A no-show cannot happen while a match fills, so the "4 occupying seats books the match" rule is
   unchanged.
3. **§1.9's staff title key needs `notify_staff` re-issued, and §1.8 does not list it.**
   `app.notify_staff` checks `title_key` against a constant array in its body (0193:47-57) and
   raises `INVALID_ARGUMENT` for any other key. **Fix:** add a §1.8 row: `notify_staff`, latest
   0193, owner DB (0257, with `match_report`), adding `match_report_new`. `_shared/staff-push.json`
   and `send-push/staffStrings.ts` (EN and AR) gain it too, and `send-push` is deployed before the
   migration reaches hosted, as that file's `_readme` requires.

### Open technical questions

1. **Who writes off a walk-out.** §1.7 makes `match_seat_write_off` manager/owner and PIN-gated, so
   a manager must be signed in at the desk and also type a PIN. The till's `apply_discount` model
   (the clerk starts it, a manager's PIN authorises it, since `verify_manager_pin` only mints grants
   for manager and owner PINs, 0156:484) fits a walk-out at a busy desk better: roles court_desk,
   manager, owner, plus the PIN grant. `writeOffSeat` would then be court_desk, manager, owner.
   Recommendation: take the till model. It needs Parsa's yes.
2. **DF-16's wall.** Which call refuses café lines on a match booking, and with which code? The desk
   hides its two entry points; the till's booking picker (`NewTabDialog`, cashier) cannot tell a
   match booking apart without a `desk_match_states` read, which the cashier is not granted. Money
   §3 has to name the refusal (`open_tab` with orders, or `merge_tabs` into a match booking's tab),
   and it must still allow the court-only booking tab the offline path opens.
3. **An open booking tab and `match_seat_settle`.** A live booking tab (opened offline, or through
   the booking-level Cash/Card) blocks a fresh seat tab (`tabs_one_live_per_reservation`,
   0106:113). This lane assumes Money refuses `BOOKING_TAB_OPEN` and the desk settles that bill and
   Assigns it. If Money settles on the live tab instead, only the pane's copy changes.
4. **Switching matches off with matches in flight.** Nothing in §0 says what happens to filling or
   booked matches when `matches_enabled` goes false. The settings copy assumes they go on and only
   new starts stop.
5. **Undoing `attended` after the ticket was used again.** If the released ticket is already locked
   in another match, the undo cannot re-lock it. This lane assumes the server refuses
   `SEAT_MARK_LOCKED`.
6. **Unmarked seats at completion.** This lane assumes an unmarked seat becomes `attended` (owes the
   share) when the booking is completed, and says so in the Players footer. §2 decides.
7. **The phone's landing for `match_report_new`.** The staff phone has no reports screen; route
   `staff` opens its home. Is a rail badge on Ops wanted as well (`lib/workspaces.ts:75`, a closed
   union)? Not built in v1.
